# Reflection — Laboratory Activity 1

**Name:** Fernando Echanes

Completing this onboarding mission gave me a hands-on introduction to what
day-to-day cloud engineering work actually looks like. Setting up a new
Linux user account with proper sudo access and a home directory felt
simple on the surface, but it reinforced why access control matters in
real infrastructure environments — every account should be created
deliberately, not assumed.

Gathering system information (distribution, kernel version, CPU, memory,
and disk space) showed me how much diagnostic detail is available right
from the terminal, and why cloud engineers rely on these commands before
deploying or troubleshooting services.

Building the workspace folder structure and documenting everything in
Markdown also highlighted a habit I'll need throughout this course:
treating documentation as part of the actual work, not an afterthought.
Finally, structuring my GitHub repository as a portfolio made the task
feel less like a one-off assignment and more like the start of a running
professional record I'll build on every lab from here forward.

Overall, this mission set a solid foundation in Linux navigation, system
diagnostics, and version-controlled documentation that I expect to rely
on heavily as the semester moves into Git, Docker, and Kubernetes.
